# tools/ の仕分け

このディレクトリには、開発の過程で作った 28 本のスクリプトがある。
**どれが今も使うもので、どれが記録として残しているだけかが分からなくなった**ため、
全部に分類を付けた(D-039 の着手順 2)。

**ファイルは消していない。** 過去に何を試して駄目だったかは、
同じ道を再び通るときの出発点になる。ただし**「置いてある = 使う」ではない**ことを、
この表ではっきりさせる。

## 分類

| 記号 | 意味 |
|---|---|
| **配布** | インストールに要る。**手順 3 で書き直す土台** |
| **開発** | 実機の診断・採取に使う。手元でだけ動かす |
| **不使用** | 現行構成では使わない。**なぜ使わないかの記録として残す** |
| **一度きり** | 特定の調査のために作った。再利用しない |

**パスが `E:\build\Foilwright` で固定されているものが 18 本ある(34 箇所)。**
**直していない。** 配布に要るものは手順 3 で新しく書くため、既存を直す作業は
そのまま捨てる作業になる。**「開発」「不使用」「一度きり」のものは手元でしか動かさない**ので、
固定のままでよい。

## 配布

| スクリプト | 何をするか |
|---|---|
| `setup-printer-b.cmd` | **Windows 同梱の `MS Publisher Color Printer` で仮想プリンタを作る**(D-022)。署名もドライバパッケージも要らない。**これが現行の動作構成**。ただしポートは `FILE:` のままなので、次の 1 本と組で使う |
| `setup-pipe-port.cmd` | 名前付きポート `\.\pipe\foilwright` を作り、プリンタをそこへ向ける(D-023)。**トレイアプリが受け取る口** |
| `rebuild.ps1` | トレイを止める → ビルド → 起こす → パイプ確認(§15.12)。**開発者向けだが、動作確認の手順として配布物にも要る** |
| `make-package.cmd` | **`make-package.ps1` をダブルクリックで動かせるようにした包み。**PowerShell を知らなくても配布物を作れる。終了時にキー待ちで止まるので、窓が消えない。**インストールは行わない**(プリンタにも触らない) |
| `make-package.ps1` | 配布物を組み立てる。`dotnet publish --self-contained` → 設定を集める → `install.ps1` / `uninstall.ps1` / `README.txt` を添えて zip(D-041)。出力は `dist/`(追跡対象外) |
| `package/install.ps1` | **zip に同梱される導入スクリプト。** 管理者権限と Ghostscript を確認 → `%LOCALAPPDATA%\Foilwright` へ配置 → ポート → プリンタ → 自動起動 → トレイ起動とパイプ確認。**何を入れたかを `install-manifest.json` に記録する** |
| `package/uninstall.ps1` | **zip に同梱される削除スクリプト。** manifest を読み、**自分が入れたものだけ**消す。manifest が無ければ何もしない。設定は既定で残し `-Purge` で消す。`-WhatIf` 対応 |
| `package/README.txt` | zip に同梱される利用者向けの手順 |

**配布に関係するのはこの 7 本である。**

**`.cmd` は逆に、BOM 無し・ASCII(英語)で書くこと。** 既存 18 本すべてがそうなっている。
**日本語を `.cmd` に直接書くと cp932 で壊れる。** 利用者に見せる日本語は
PowerShell 側(BOM 付き UTF-8)に喋らせ、`.cmd` は起動と後始末だけを担う。
`.cmd` の改行は **LF**(既存 18 本すべて LF)。

**PowerShell スクリプトは UTF-8 **BOM 付き**で保存すること。**
**BOM が無いと PowerShell 5.1 は ANSI(cp932)として読み、日本語の文字列が壊れて構文エラーになる。**
2026-08-20 に新規作成した 4 本を BOM 無しで保存し、`uninstall.ps1` が
「文字列に終端記号 ' がありません」で動かなくなった。**既存の 10 本はすべて BOM 付きであり、
その流儀を破ったのが原因だった。**

## 不使用

**自作のプリンタドライバと自己署名証明書を使う方式のもの。**
**現行構成では使わない**(D-039)。実測で確かめた:

```
DriverName : MS Publisher Color Printer   ← Windows 同梱
自作ドライバの登録数: 0
```

他人の PC に「この証明書で署名されたものを全部信頼させてください」と頼むのは、
説明が重く、実際に危険でもある。**それが不要と分かったことが D-039 の要点である。**

| スクリプト | 何をするか | 残す理由 |
|---|---|---|
| `install-printer.cmd` | 自己署名証明書を `LocalMachine\Root` と `TrustedPublisher` に入れ、自作 PPD をドライバストアへ導入する | **D-039 が「使わない」と判断した対象そのもの。** 消すと、なぜ使わないのかを次に読む人が確かめられない |
| `add-printer-driver.cmd` | 導入済みパッケージをプリンタドライバとして登録する | 同上 |
| `cleanup-driver.cmd` | `ERROR_PRINTER_DRIVER_BLOCKED` でドライバストアに残ったパッケージを消す(§3.5.1) | **後始末の手順**。将来ドライバを自作するなら再び要る |
| `remove-cert.cmd` | 試験のために信頼させた自己署名証明書を消す(§3.5.1 / D-022) | 同上。**入れたものを消す手順は残しておく** |
| `sign-package.ps1` | パッケージに署名する | 同上 |
| `setup-port-b.cmd` | ポートを `FILE:` ではなく固定ファイルに向ける | `setup-pipe-port.cmd` に置き換わった |

## 一度きり

特定の調査のために作ったもの。**再利用しない。**

| スクリプト | 何のための調査だったか |
|---|---|
| `diag-driver.cmd` | `Add-PrinterDriver` が返す失敗コードを正確に採る |
| `test-inbox-ps.cmd` | 同梱の PostScript ドライバがこの Windows で入るかを見て、`ERROR_PRINTER_DRIVER_BLOCKED` が第三者パッケージ固有かを切り分ける |
| `capture-mecherr.cmd` | 純正ドライバが機構エラーを表示している最中のバスを採取し、**種別をどこから得ているか**を探す。§14.6 のとおり USBPcap と VMware の併用に失敗して打ち切った |
| `verify-after-reboot.cmd` | USBPcap を外して再起動した後、プリンタの経路が戻ったかを順に確かめる |

## この表を更新するとき

**スクリプトを足したら、必ずこの表に 1 行足す。** 分類の無いスクリプトが増えると、
またすぐ「どれが現役か分からない」状態に戻る。

**分類が変わったら書き換える。** たとえば手順 3 で新しいインストールスクリプトを
書いたら、`setup-printer-b.cmd` と `setup-pipe-port.cmd` は「配布」から
「不使用(新スクリプトに置き換わった)」へ移る。
