# PROJECT ARCHITECTURE: Foilwright

現状: 実装未着手。リポジトリは docs のみで src/・ref/・tests/golden/ は未作成(2026-07-27 時点)。

## 目的とスコープ

- 解決する課題: ALPS MD シリーズ(MD-5000 / MD-5500)の公式ドライバが 32bit 版のみで 64bit Windows では動作しない問題を解消する。任意のアプリの印刷ダイアログから通常のプリンタとして選択でき、白・金銀を含む特色印刷が可能な 64bit ネイティブの印刷経路を提供する(DOMAIN §1.1)。
- Phase 構成(DOMAIN §9.4):
  - Phase 0: 環境調査(ポート一覧・変換ケーブルのデバイス ID 取得のみ、実機リスクなし)
  - Phase 1: 5mm 角のベタ 1 色を 1 枚(プロジェクトの成否を決める関門。§11.2 のタイミングリスクがここで判明する)
  - Phase 2: 仮想プリンタ経由でメモ帳から印刷
  - Phase 3: 白版を含むフルパス(外部協力者への配布はこの成立後に限る)
  - Phase 4: MD-5500 USB 直結対応(Phase 3 成立後に着手。DOMAIN §11.3)
- 明示的な非目標(DOMAIN §1.3):
  - 昇華モード(ダイサブ)への対応
  - Windows 以外の OS
  - v4 プリンタドライバ形式
  - 難読化・解析対策
  - なお MD-5500 の USB 直結対応は非目標ではなく保留(Phase 4 として実施予定)

## レイヤ構成

四層構造、依存方向は L3 → L2 → L1 → L0 の一方向のみ(逆流禁止)。特に L0 と L2 は機種を一切知らない。機種差は L1 のプロファイルに閉じる(DOMAIN §3.1)。

### L0 transport
- 責務: 物理経路への書き込み
- 触ってよい/いけない境界: バイト列を受け取って送出する以上に具体化しない。ポート名やプリンタキュー名を L1 以上に漏らさない(DOMAIN §11.3)

### L1 emitter
- 責務: MD コマンド生成 + 機種プロファイル
- 触ってよい/いけない境界: 機種による分岐はここに閉じる。`if model == "MD-5500"` のような条件分岐がプロファイル定義の外に現れることは設計違反(DOMAIN §4.4)

### L2 raster
- 責務: 画像 → インク別 1bit プレーン

### L3 interface
- 責務: PPD / ポートモニタ連携 / トレイアプリ

## データフロー

DOMAIN §3.2 の経路図(そのまま引用):

```
アプリケーション(Photoshop / Illustrator / ペイント等)
  ↓ 印刷ダイアログでプリンタを選択
Microsoft PostScript Printer Driver V3 + 自作 PPD
  ↓ PostScript
Windows スプーラ
  ↓
mfilemon(ポートモニタ / 既製品・改造しない)
  ↓ パイプで標準入力へ
Foilwright 変換器(セッション 0 / UI を持たない)
  ↓ ジョブをキューフォルダに積んで即終了
Foilwright トレイアプリ(ユーザーセッション / UI を持つ)
  ↓ WritePrinter (RAW)
Generic / Text Only プリンタ → USB001 → USB-パラレル変換ケーブル
  ↓
MD-5000 / MD-5500
```

内部座標は常にドット単位。mm は L3 の入口(PPD 解釈)でのみ扱う(DOMAIN §4.1)。

## 主要データ構造 / IR

IR は「インク名 → 1bit プレーン」(DOMAIN §4.2 / §6.4)。マジックカラー方式・ページ分割方式のいずれを入口に使っても、L2 以降のこの内部表現は同一。

- 保存しないもの: `auto_backing`(他インクが乗る画素の和集合として導出されるプレーン)は保存せず、必要時に導出する(DOMAIN §6.2)
- 初版は閾値二値化のみを実装し、ディザリングは実装しない(DOMAIN §4.2)

## 外部依存とその理由

| 依存 | 用途 | 代替を却下した理由 → DECISIONS |
|---|---|---|
| mfilemon(ポートモニタ・改造しない) | スプーラからのジョブをパイプで変換器の標準入力へ渡す | — |
| Microsoft PostScript Printer Driver V3 + 自作 PPD | 印刷ダイアログに通常のプリンタとして見せ、PostScript を受け取る経路を提供 | D-001, D-002 |
| ppmtomd(golden 生成元・リポジトリ非同梱、DOMAIN §8.2) | 実装の正しさを判定する基準バイト列(golden)の生成元。他者の GPL コードであり配布の責務を負わない | D-007 |
| Ghostscript(非同梱、DOMAIN §12.2) | md5k ドライバ等の解像度対応状況の参照。AGPL のためバンドルしない | — |

## 既知の制約 / 未解決

DOMAIN §11 に判断待ち・実測待ちの項目が 8 件ある。要約(詳細は DOMAIN §11):

1. 変換ケーブルの双方向対応状況(実機 + 知人へのヒアリングで解決)
2. カラーマネジメントによる RGB 変位の有無と量(実測で解決)
3. MD-5000 と MD-5500 のコマンド差分(golden の差分取得で解決)
4. `max_width_dots` の実値(実測または ppmtomd のソースで解決)
5. サードパーティ製スポットカラーインクの使用条件(販売元への直接確認。現時点で設計影響なし)
6. 2400dpi の実体と到達可能性(ppmtomd のソース読解で解決。現方針は 1200x600 を上限とする)
7. スプーラ経由でのタイミング成立性(Phase 1 の実機試験で判明。**経路そのものの成否を決める最重要リスク**)
8. MD-5500 の USB 直結対応の難易度(実機のデバイスマネージャ確認で解決。Phase 4 で対応)

詳細は DOMAIN §11。
